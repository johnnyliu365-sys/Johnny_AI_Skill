## Requested observable outcome

An opted-in project's reviewer invokes a bounded verification action for one exact ticket and
candidate. A program resolves the approved execution plan, refuses altered or unsupported plans
before execution, enforces the authorized resource/lifetime limits, and returns independently
checkable evidence to the existing Router. The Agent does not invent repetition counts, load,
clean-export work, retry loops or additional acceptance requirements at execution time.

The existing WA-04 responsibility-admission slice must be delivered rather than duplicated:
ticket-declared responsibilities, dependency direction, construction ownership and test seams
must be checked against actual candidate source before integration. Passing a line-count check
or splitting one coupled file into many mutually dependent files does not satisfy this outcome.

## Requirements to freeze in the specification

1. The approved plan binds project/ticket, candidate SHA, policy revision, ordered run conditions,
   expected checks, permitted infrastructure retry classes, per-run and total deadlines, resource
   limits, execution adapter, cleanup and evidence destinations. A caller-supplied ID/digest is
   an assertion to resolve, not authority to mint an approved plan.
2. Profile templates may propose a plan. An invocation cannot freely switch its profile, increase
   repetitions/load, substitute a candidate or enlarge a limit. Changed intent returns to review;
   it cannot rewrite a previously approved requirement implicitly.
3. Preserve every attempt and failure. Never retry assertions until green or drop failed runs from
   a consecutive-success claim. Empty collection, unknown result, timeout, cancellation, cleanup
   failure and an unperformed review are distinct from success.
4. Execution hard-limits and cleanup follow the existing EC-10 requirement. Unproven mandatory
   controls refuse the affected execution path; they do not block unrelated read-only planning,
   source-contract work or same-lifetime delegation. No unlimited busy loop is an allowed fixture.
5. Runtime process waiting is bounded and event/exit-driven. The model does not repeatedly tail,
   re-read or query task activity. Interrupted execution requires evidence reconciliation before
   resuming; a stale task item does not authorize duplicate work.
6. The existing Router consumes a typed result with pinned evidence identity. A JSON PASS alone,
   a filename, a commit or a caller-authored review count is insufficient completion proof.
7. Skill and shared engine stay Johnny-owned; native project source, tests, approved plans and
   review artifacts stay target-owned. No copied `.workflow/skills` governance tree or target
   runtime import of Johnny is introduced.
8. Both Codex and Claude Code remain required supported hosts, with independent qualification.
   Bypass prevention, local integration refusal and remote enforcement must be reported separately.
9. WA-04 remains the owner of source-responsibility admission. New verification components must
   have an approved responsibility map and adversarial dependency/construction mutations. Do not
   append the entire feature to the existing large `contracts.py` or `router.py`.
10. Natural language may propose an amended plan but cannot change the approved executable plan.
    Approved source, executable/argv, script/dependency identities, working snapshot and bounded
    environment must be resolved by the executor itself, not trusted from the Agent's command.
    Exact repetition counts and ordered load conditions include the distinction between five
    runs with one loaded run and five loaded runs. An unchanged argv with changed script bytes
    must not bypass candidate binding. A hash check followed by mutable execution is not proof.
11. Process lifetime belongs to one attempt. Cancellation, total deadline, owner loss and executor
    crash must have independently tested cleanup semantics. Only proven-owned process trees and
    resources may be terminated; names or bare reusable PIDs are insufficient authority. Cleanup
    failure preserves recovery evidence and prevents a new dependent attempt.
12. Reconciliation distinguishes completed work with stale host UI, live owned work, interrupted
    work with no terminal result, and conflicting or unverifiable evidence. Duplicate invocation
    must not start duplicate work; missing completion evidence is never manufactured. This is
    local execution recovery, not a queue or receipt prerequisite for synchronous delegation.
13. Normal execution uses event/exit waits and finite deadlines, not Agent polling. SessionStart
    instruction injection and a successfully invoked Skill are not enforcement evidence. User-level
    registration holds executable entry/version references, not a second governance prose copy.
14. Every claimed enforcement boundary must survive its declared bypass tests: direct shell,
    existing interactive stdin, alternative effect tools, hook failure/disablement, altered policy,
    process escape and forged evidence. An unprotected path cannot be labeled mandatory. Narrowing
    actual host/OS permissions requires the owner's scoped decision before changing them.

## Owner-requested delta D4: compact, enforceable implementation dispatch

On 2026-09-17 the owner requested separate readers: the reviewer/control plane retains the
complete TICKET history, review, correction and convergence; the implementer receives only the
current DISPATCH work packet. The requested rendered sections are **Ticket, Objective,
Authority / baseline, Allowed files, Forbidden files, Preserve, Work, Acceptance, Run, Return**.
Return contains status, candidate, files, checks, findings and deviations. This is a requirement
to reduce actual implementer input, not a request to add another full document to that input.

Required behavior to converge in the affected specification:

1. TICKET remains the approved authority. DISPATCH is a generated, versioned projection of its
   current approved contract and selected work slice, not an independently edited authority or
   model-written historical summary. The generator consumes explicit structured contract fields;
   it cannot prove semantic completeness of arbitrary prose. The reviewer owns approval of the
   source contract and which requirements apply to the slice.
2. Before dispatch, validate exact ticket identity/revision/digest, closure and slice, baseline,
   owner/worktree/branch and approved model-profile binding. Rebinding or superseding these
   inputs invalidates the old packet; retrying an existing admitted dispatch must not start a
   duplicate lane. Reuse the existing dispatch lifecycle; no new runner, queue, receipt issuer or
   cross-lifetime bridge is required for the synchronous path.
3. Check complete coverage of the approved slice: every required Work, Acceptance, Run and
   Preserve entry must resolve to the source contract. References may be many-to-many. Reject
   missing entries, invented entries and conflicting file permissions; an explicit prohibition
   wins. Preserve unchanged invariants and closed findings without copying their full review
   history or silently reopening them. Necessary public interfaces, type/security constraints and
   test obligations must remain present or resolvable through exact bounded references.
4. Run resolves to the already approved structured execution plan, including executable/argv,
   working snapshot/script identity, order, counts, load conditions, timeout and retry bounds.
   Objective/Work prose cannot authorize extra verification. Preserve the distinction between
   five runs with one loaded run and five loaded runs. Execution enforcement remains the
   qualified executor's responsibility; comparing a Markdown command or hash alone is not proof.
5. Return binds the exact dispatch digest and candidate. The reviewer/gates independently read
   the actual diff and execution evidence; a caller's files list or PASS is not acceptance.
   Out-of-scope work or changed requirements follow the existing BLOCKED/CHANGE_DETECTED route.
   Compact input must not reduce required first-red, reverse-mutation or unreduced review evidence.
6. The implementer input builder must not attach the full parent conversation or historical
   TICKET/review/correction/convergence bodies. Machine binding metadata belongs in the contract;
   the rendered packet keeps the owner's compact sections without an arbitrary line-count gate.
   Reusing an Agent does not erase its earlier context. Claim input minimization only unless
   independent host qualification proves a stronger context/filesystem/tool isolation boundary.
7. Update the applicable reader/admission paths for both Codex and Claude Code together. The
   current [dispatch normalization](../../../../../skills/johnny-project-takeover/references/specification-ticketing.md#dispatch-normalization)
   resolves the complete contract from the exact ticket. Adding DISPATCH while still requiring
   every implementer to load the whole ticket would not meet this change. Mandatory governance
   remains applicable; do not copy it into a second host-global prose source.

The subsequent implementation must include rejection fixtures and reviewer reverse mutations
for a missing Preserve/Acceptance entry, a stale ticket or baseline, a repeated dispatch,
expanded run/load bounds, a forbidden-file change and a mismatched return. Admission validation
and actual host/effect enforcement are separate claims. An unrestricted alternative dispatch or
shell path prevents claiming the latter, even when the packet validator passes.

This delta is recorded for scoped impact analysis and specification convergence. It does not
silently amend the sealed Context, approved qualification SPEC or CVQ-01 closure. In particular,
it is not approval of CVQ-01's separately pending two-phase preflight exception. No implementer
dispatch, hook/source change, VM effect, integration, push or release is authorized by this record.

## Owner-requested delta D5: deterministic review and descendant cost control

The owner requires scripts to perform repeatable checks without recurring model reasoning,
bounded adversarial work, and enforceable test-code responsibility boundaries. Parent-only
restrictions are insufficient. The requested automation percentages describe a desired division
of work, not measured defect-detection rates: automated secret/dependency scans do not prove
absence of unknown leaks/vulnerabilities; RLS presence does not prove correct tenant isolation;
pixel equality does not prove usability; mutation scores cover only the selected operators.

Required behavior to converge with D4, without creating a second workflow engine:

1. Reuse registered, version-bound check adapters for compile/type/lint, existing unit and
   integration/regression suites, Git/path admission, contract/security/visual/performance checks
   and finite mutations. Model reasoning owns requirement meaning, architecture, trust boundaries,
   contradictory specifications and novel failure hypotheses. Automated execution is not automated
   invention of sufficient tests, and a green check is not review approval.
2. One approved task budget covers the parent and all descendants, resumed owners, retries and
   execution attempts. The protected controller allocates non-expandable child allowances; an
   Agent cannot mint another lane or reset accounting by restarting. Actual tool/provider effects
   must be mediated, not merely described in prompts. Bind finite concurrency, calls, deadlines,
   execution resources and model input/output allowances to the approved plan. Unknown usage is
   not zero; unsupported host accounting/enforcement cannot be labeled a hard token cap. Exhaustion
   stops new admissions and preserves bounded cancellation/cleanup/recovery capacity.
3. Keep the existing adversarial helper read-only/no-code/no-delegation boundary, now requiring
   qualified enforcement for that claim. It returns finite hypotheses/findings tied to the current
   Closure; it may not create a new test runner, grow the matrix, rerun every check, or launch peers.
   Missing cases return to the reviewer for bounded admission and the original implementation owner
   where code is needed; they do not automatically trigger another audit round or new acceptance.
4. Apply the existing WA-04 responsibility contract to test code, fixtures and temporary audit
   harnesses as well as production code. Separate orchestration, environment/process lifecycle,
   evidence reporting, domain assertions, fixtures and mutation operators. Prefer new cases in an
   existing parametrized suite over copied runners or generic helper frameworks. Enforce declared
   paths and dependency direction with source/AST checks; an undeclared runner or dependency rejects.
   Line counts, file counts and renamed/mechanically split coupled modules are not proof of quality;
   remaining semantic responsibility questions still require reviewer judgment.
5. Execute the approved check plan without model polling or model calls inside deterministic
   runners. Deduplicate only accidental requests for the same bound execution slot, never the
   intentionally repeated runs, TDD stages or independently required reviewer mutations. Evidence
   reuse must match source snapshot, test/runner/dependency/config identities, environment, policy,
   phase and any required observation role; changed or unverifiable inputs invalidate it. Preserve
   failed attempts. Adapters must reject empty/unexpected collection and incomplete cell manifests.
6. Propose a machine-evidence review route: a trusted verifier accounts for every expected cell and
   retained failure, binds raw evidence identities and emits a compact structured report. Preserve
   complete appropriately protected/redacted evidence; do not truncate it away. The AI reads the
   finite report and required semantic/source slices, opening exact raw evidence for failures,
   mutation causality, inconsistencies or required independent checks. A hash or self-authored PASS
   alone is insufficient. The current [output-reduction rule](../../../../../skills/johnny-project-takeover/references/context-routing.md#output-reducing-capabilities)
   requires unreduced output in review/smoke; this proposed route needs an explicit canonical policy
   revision and cannot silently replace that requirement. Unsupported adapters remain unqualified.
7. Measure parent-plus-descendant model input, cached input where observable, output, calls, repeated
   execution and evidence-read volume against comparable completed work with unchanged acceptance.
   Script CPU/runtime is separate from model tokens; tool return text and AI-written/read scripts
   still consume model context. Reuse available telemetry, record unavailable data explicitly, and
   do not claim a savings percentage or a zero-token workflow before measurement.

Acceptance must exercise descendant self-delegation/budget-reset attempts, forbidden test-harness
dependencies, accidental duplicate execution versus required repeated slots, stale reused evidence,
omitted/failed/uncollected cells and missing usage. A mandatory independent adversarial check is not
removed to save cost. Numeric budgets and adapter contracts remain to be specified, not invented here.
This is a pending scoped requirement change, not a modification of skills, sealed Context, approved
qualification contracts or CVQ-01's pending exception. No runtime or host enforcement is claimed.

qualification are draft design until the owning SPEC/Context/ticket gates close. No new production
