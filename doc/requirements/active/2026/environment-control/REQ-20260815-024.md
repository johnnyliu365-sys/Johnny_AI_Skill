# Isolated environment capability bootstrap

| Field | Value |
| --- | --- |
| PRD / change | `PRD-20260815-024` / `CHG-20260815-024` |
| Lifecycle | `ACTIVE` |
| Requirement | Before Johnny controls or dispatches work for a project, resolve only the capabilities required by the current workflow gate. Reuse compatible user/project tools first; otherwise install only reversible per-user Johnny-owned tools or guide the user through separately approved system, login, EULA, reboot or external-effect work. Control tooling, project-native tooling and ticket execution remain isolated. No Johnny-specific runtime, environment manifest, cache, worktree or telemetry path may be written into the target project. |
| Resource requirement | Every Johnny-launched process or container uses an exact finite CPU, memory, disk, process/container, worker and lane plan. Unsupported hard enforcement halts before launch. Capability checks and drift readback occur only at declared boundaries; there is no heartbeat, scheduled polling or background update. |
| Ownership / removal | Project files remain project-owned. Johnny-owned environments, caches, grants, evidence, receipt bindings and runtime state live under the per-user Johnny root and are removed only by exact project detach or plugin uninstall ownership records. Foreign/user tools and target projects are never removed or modified. |
