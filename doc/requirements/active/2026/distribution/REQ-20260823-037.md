## Change record

| Field | Value |
| --- | --- |
| Old rule | The repository verifier compared every admitted ref, including every retained immutable release tag, to one payload constructed from the current working candidate. F3 intentionally changed that declaration. Therefore a correct retained `plugin-v0.4.10` and a correct fresh `plugin-v0.4.11` could not coexist. |
| New rule | `refs/heads/main` and the new release tag for the current candidate remain path-and-blob bound to that exact candidate payload and generated root. A retained `refs/tags/plugin-v<semver>` is separately read from its own parentless target: the verifier extracts the tag's `.claude-plugin/plugin.json` payload declaration, checks its exact declared path set, checks the generated pin-carrier form, and requires the tag semver to equal the plugin and marketplace entry versions stored in that target. |
| Historical-content boundary | The immutable tag target is the provenance for historical file contents. A tag's own declaration proves its allowed tree shape, not independent blob equality to today's working tree: no historical source checkout or per-file external digest exists. The contract must state that limit rather than falsely report a current-candidate blob comparison. Current `main` and the fresh `plugin-v0.4.11` target retain the stronger candidate path-and-blob comparison. |
| Immutable-release rule | `plugin-v0.4.10` remains at `b52215eb3ee5dfa101e65c189441e62c20ca45e6`; it is neither moved, deleted nor reused. After the local contract closes, only a fresh exact Ticket 08 authority may create absent `plugin-v0.4.11` at its newly generated root. |
| Impact | Add a bounded local Git closure contract before Ticket 08 can be re-admitted. Ticket 08's CLOSURE_03 candidate, root and effect authority remain suspended review evidence; no remote or source effect is revived by this change. |

## Non-negotiable properties

1. The complete remote ref grammar remains exactly `refs/heads/main` plus zero or more lightweight
   `refs/tags/plugin-v<semver>`; an unknown ref/default branch, a parent, unreadable object,
   malformed declaration or missing/extra declared path fails closed with a finite result.
2. `main` is always checked against the current typed candidate payload, including its expected
   blob identities and reversible carrier normalization. The new release tag is additionally
   bound to the candidate's semantic version and exact generated root.
3. Every retained tag is checked from its own Git target, never against a mutable working-tree
   declaration. Its tag semver, plugin manifest version and marketplace entry version must agree;
   its embedded carrier must parse only in the generated release form.
4. The self-declaration rule does not silently turn into a content-provenance claim. A historical
   tag's declared paths are exact, but its declared-file bytes are trusted through its immutable
   target and pre-release evidence, not compared to current development blobs.
5. Ticket 12 is local/read-only against disposable Git fixtures. It must not create a real ref,
   tag, repository, candidate pin, source push, user cache or Claude CLI invocation.
6. Ticket 08 remains blocked until Ticket 12 is integrated and an owner supplies a new, exact
   effect authority. The suspended CLOSURE_03 authority cannot be refreshed by inference.
