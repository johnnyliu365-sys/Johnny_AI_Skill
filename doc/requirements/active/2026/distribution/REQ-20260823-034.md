## Non-negotiable properties

1. A successful install may create Git metadata in the plugin cache, but no development-repository
   commit, tree, blob, ref or path may be reachable there.
2. Every commit reachable from every publication-repository head or tag is parentless and its tree
   is exactly one generator-declared payload. `tests/`, `doc/`, `modules/` and every other
   undeclared path are absent by construction, not deleted after clone.
3. `main` names the currently advertised payload. `plugin-v<semver>` is immutable and names the
   same commit for that version. No version tag is moved or reused; changed payload requires a
   version increment.
4. Updating publication `main` is a guarded compare-and-swap using the read-back old SHA. A stale
   old SHA, non-empty unexpected remote, extra ref, wrong default branch, non-payload tree or tag
   collision fails closed before the development-repository pin changes.
5. End-to-end evidence uses an isolated `CLAUDE_CONFIG_DIR` and the actual documented commands.
   It compares visible paths and blob identities to the declared payload, enumerates every
   reachable ref/commit in the installed plugin cache, and applies the payload difference check
   to each tree. A green checkout alone is insufficient.
6. Repository creation, remote ref mutation, release publication and public README cutover remain
   explicit external effects. This requirement authorizes their design, not their execution;
   the future ticket and owner authority must name each effect.
7. Until the Context and SPEC are revised and tickets are owner-approved, this leaf returns
   `REQUIREMENT_CHANGED` and is not implementation, publication, push or release authority.
