## Decision record

`plugin-v0.4.10` is immutable and already names publication root
`b52215eb3ee5dfa101e65c189441e62c20ca45e6`. F3 integrated at
`7a64f6312d8cd2a84a8821eb1dac2f00e205c8b7` and changes the declared Level 1 payload, so that
root cannot be reused. The owner selects `0.4.11` as the one successor release version.

`0.4.11` is a patch successor because F3 preserves the installed Claude skill/command interface
and reusable-source purpose; it removes only host-local tooling that was not a valid detached
plugin runtime capability. This decision does not reinterpret the already immutable `0.4.10`
tag, turn a historical candidate into a current candidate, or authorize a release effect.

## Non-negotiable properties

1. A future Ticket 08 candidate uses version `0.4.11` in both Claude manifests, a new generated
   root and, only after exact owner effect authority, an immutable `plugin-v0.4.11` tag. It never
   reuses, moves or deletes `plugin-v0.4.10`.
2. The version, source URL, generated root and marketplace SHA remain one candidate transaction.
   The SHA is generator-derived and is never hand edited to fit `0.4.11`.
3. Every external operation remains unapproved by this requirement: no remote/ref/tag mutation,
   source push, marketplace descriptor publication, isolated Claude CLI run or user-cache change
   occurs until a fresh Ticket 08 owner effect record names its exact baseline, candidate,
   expected-old remote SHA, correlation and targets.
4. Ticket 08 keeps all L1–L6 proof obligations. Its former `0.4.10` effects and evidence are
   historical only; F3's local tests do not substitute for a fresh publication/cache closure run.

## Acceptance source

Sealed Context Revision 03, owner-approved Specification Revision 04 and a Ticket 08 re-admission
record that binds `0.4.11` without creating an external effect. The later effect-authority record
is a separate owner decision, not an implication of this version choice.
