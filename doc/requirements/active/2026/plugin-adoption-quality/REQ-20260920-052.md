## Confirmed defect and narrow source correction

The development runbook contained the full model/effort registry; the publication declaration
excludes the development documentation tree. The installed cache has no such runbook. The skill
and model-role reference required a profile but did not route to a bundled concrete registry.
This is a reproducible delivery/routing gap, not proof of a host credential or model failure.
Root confirmed the declaration, publication exclusion, skill routing and absent installed file;
a bounded read-only helper independently found the same gap. The particular user's failed
session was not locally reproduced, so no unique transcript-level cause is asserted.

The source correction creates one canonical
[bundled dispatch profile](../../../../../skills/johnny-project-takeover/references/dispatch-model-profile.md),
links it from the skill/model routing and changes the old runbook to a pointer. The existing
skill tree is already allowlisted: no development tree is added to the payload. Defaults apply
when a new target lacks its own profile, not when an explicitly pinned profile is broken.
The existing Codex role/model/effort intents are preserved. Claude mapping remains explicitly
unconfigured in the absence of an approved host profile; do not revive superseded values,
claim credentials, switch providers or infer a more expensive model. Both hosts must resolve
the same shipped reference, with separate actual capability/installed qualification.

This is a docs-only source-policy correction authorized by the owner's explicit request.
It neither installs the modified plugin nor implements a protected dispatch interceptor.

## Source content rule

The canonical [source-content boundary](../../../../../skills/johnny-project-takeover/references/source-content-boundary.md)
is now routed from implementation and review. It bans owner/dispatch prompts, ticket bodies,
acceptance lists, correction history and transcripts in comments, docstrings and incidental
strings. Necessary technical comments and license notices remain. Product-owned prompt/ticket
processing needs its own approved responsibility; it is not an exception for arbitrary copied
instructions. Rejection fixtures must be explicitly scoped synthetic data, not live messages.
The rule applies to parent and child work, tests and temporary audit code alike.

This review obligation is effective in the revised source, but **no executable content gate is
claimed implemented**. A finite scanner can prove named lexical/structural predicates, not the
absence of every paraphrased instruction. Future admission must identify language support,
violation codes and source locations, retain semantic reviewer responsibility, and prove
rejection with negative controls and independent reverse mutations. Do not use a growing
keyword list or a model-authored PASS as universal semantic proof.

## Responsibility enforcement: existing owner, still an implementation gap

The owner again rejects coupled source/scripts, not merely long files. The WA SPEC already
assigns responsibility admission to WA-04, but the current WA ticket registry has no opened
WA-04 leaf. [CVE-04](../../../../../modules/tickets/controlled-verification/cve-04-wa04-test-boundary-amendment.md)
revision03 is only a CONTROL_PLANE_TICKET_PROPOSAL, NON_DISPATCHABLE. It extends the same
future validator to assertions, fixtures, mutation operators, orchestration, environment/process
lifecycle and evidence. Therefore neither the proposal nor this policy correction is a delivered
anti-coupling gate. Do not claim the problem is already solved.

Carry the following into that existing WA-owned implementation contract, not a second engine:

1. Before development, bind each module's owned behavior, public interfaces, allowed/forbidden
   dependencies, composition/construction ownership and test seam in an approved contract.
   The implementer cannot write the policy after its candidate to legitimize a violation.
2. Validate actual changed production, test and script sources against that contract. Reject
   forbidden imports/construction, undeclared units/runners and missing seams using explicit
   language-specific predicates. Record unsupported/dynamic surfaces honestly, not as a pass.
3. A local check offers early feedback; the reviewer/integration boundary independently reruns
   it on the exact candidate. Qualified enrolled execution must additionally reject unregistered
   ephemeral harnesses. Integration rejection and prevention of development-time execution are
   separate guarantees; unrestricted shell/alternate-tool paths invalidate the latter claim.
4. Test a short mixed-responsibility fixture and mechanically split coupled fixture as negative
   controls, and a large cohesive fixture as a positive control. No line-count ceiling. Remaining
   semantic architecture judgments belong to the reviewer and owner, not an AST classifier.
5. Fold source-content checks into the same declared source admission surface, with separate
   rule ownership from dependency analysis. Do not append all concerns to one large module or
   let an adversarial helper implement another generic scanner/runner.
