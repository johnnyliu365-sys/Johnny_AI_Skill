## Effective product requirement

Provide one automatically discoverable `co-design-ui` skill inside the Johnny plugin for both
Codex and Claude Code. Starting from a product goal, existing UI or plain design brief, it must help
the owner compare materially different visual directions, select one target-owned UI regime
candidate for canonical CONTEXT sealing, derive feature-level UI contracts, and review implemented
screenshots across required states and breakpoints when visual verification is available.

No Figma account, external designer or design-craft provider is mandatory. When an authorized
Figma, image-generation or other design-craft capability exists, it contributes candidates or
audit findings only. When none exists, the workflow uses target-owned briefs, tokens and reference
markup. Renderer availability is classified separately: use screenshots when proven, artifact-only
owner comparison when that is all the host supports, or wait explicitly when neither exists. The
owner remains the design decision maker.

## Non-negotiable properties

1. At least two proposed directions must differ in hierarchy, typography, density, component
   language and motion/interaction character; colour swaps are not distinct directions.
2. No direction becomes implementation authority until the owner explicitly selects it. The
   selection creates a candidate only; the canonical `context-routing.md` CONTEXT stage seals one
   approved revision, which later feature tickets reuse.
3. Every feature contract covers loading, empty, success, validation error, system error,
   permission/disabled and relevant offline states, plus responsive and accessibility behavior.
4. Figma, image generation and design-craft tools are optional inputs. Their output is a candidate
   or finding, never approval, review conclusion or source authority.
5. The implementation owner does not approve its own visual result. Reviewer evidence includes
   actual rendered screenshots at declared breakpoints and an adversarial visual/accessibility
   pass before owner acceptance. If actual-output verification is unavailable, completion waits
   with `VISUAL_VERIFICATION_REQUIRED` rather than claiming success.
6. Generated design artifacts are target-owned and versioned; target runtime never imports from
   this plugin.
7. Codex and Claude Code must independently prove skill discovery, the zero-tool co-design route,
   owner-selection wait and visual-review handoff against the same artifact contracts. One host's
   success cannot qualify or publish the other.
8. Behavioral qualification uses a fixed five-session evidence set per host/scenario. At least four
   must choose the intended route and all five must avoid unauthorized effect or self-approval;
   retry-until-green is forbidden.
9. UI cluster closure produces readiness only. A single shared release ticket owns the version
   bump, payload regeneration/repin, publication and fresh Codex/Claude installed readback.

## Boundary

This draft authorizes no design-tool access, image generation, Figma write, UI source change,
implementation, publication, installation or release. Exact owner approval is required before the
first ticket is opened.
