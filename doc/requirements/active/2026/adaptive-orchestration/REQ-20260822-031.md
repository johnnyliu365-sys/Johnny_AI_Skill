## Change record

| Field | Value |
| --- | --- |
| Old rule / observed gap | The installed receipt issuer can validate a worktree path, but this session's Agent-control interface does not read back a prospective implementer task's active workspace root, model/effort identity, or verified capability rank. A prompt path, shell `cd`, task self-report, and the reviewer worktree are not valid substitutes. Therefore P8R cannot be legally dispatched through the current host interface. |
| New rule | Provide one reviewer-owned host gateway boundary that exposes only typed capability readback and receipt-bound task admission. It must obtain the active task workspace root from the host, compare it to the exact registered Git worktree identity, and bind the selected implementation/reviewer profiles to host-verified capability evidence before any implementation-source or Agent-control effect. |
| Required result | A supported host returns a named, opaque task/workspace/capability readback that can be matched to the live dispatch descriptor. An unsupported host returns a finite capability result before task creation, source access, receipt consumption, branch effect, or host effect. |
| Security and ownership | Only the ticket reviewer may invoke the gateway. Raw paths, prompts, credentials, provider responses, and task transcripts stay outside durable Router metadata. Model/profile labels never grant authority. |
| Explicit non-goals | No provider login, credential storage, provider invocation, runner start, subscription, automatic wake, direct `cd`-based workspace binding, target-project runtime dependency, or changes to P8R's pure resolver boundary. |
| Rationale | A reusable host boundary prevents every ticket from treating an Agent message as proof of workspace or model selection, while retaining the existing receipt, worktree, baseline, reviewer-strength, and manual-handoff rules. |
| Impact | Create a feature Context, approved host-gateway SPEC, and one or more bounded implementation tickets. Re-evaluate P8R only after the gateway proves a compatible implementer task and profile readback; P8R is not changed or dispatched by this requirement leaf. |
| Acceptance source | Future `modules/spec/host-gateway-workspace-binding.md`; it must include adversarial readback, task/worktree identity, capability-rank, receipt replay, unsupported-host, and no-effect tests. |

## Decision boundaries for the next stage

The architecture/SPEC must choose an adapter shape without hard-coding a provider or model name.
It must define typed inputs/outputs, finite failure codes, one host readback boundary, and the
exact point at which receipt admission is allowed. It must also record whether the current Codex
collaboration host supplies the required readback; absence is a supported `CAPABILITY_UNAVAILABLE`
result, not an invitation to infer it from agent text.

This requirement authorizes requirement, Context, SPEC, and ticket planning only. Source,
host-control, Git, receipt-consumption, provider, runner, and wake effects require later approved
artifacts and their own admission gates.
