## Effective product rule

The managed-artifact runtime, not a plugin, CLI or caller assertion, is the only component that
may decide that a multi-document transaction is safe. It recomputes every applicable baseline,
containment, path-state, digest, lifecycle and post-state invariant from the exact typed plan and
current filesystem state. A plugin/CLI may submit an intent but is never proof that the invariants
hold.

## Change record

| Field | Value |
| --- | --- |
| Old rule | R09B required immediate in-memory rollback and a finite result, but did not define what survives a durable rollback/cleanup failure, how an external uncooperative writer is preserved, or which resolver failure is an ordinary finite result. |
| New rule | Before its first target effect, the runtime durably records the reversible baseline and candidate identities in a private per-worktree recovery record. | Failure rule | Recovery makes two bounded restore/cleanup attempts. If either the required restore, temporary cleanup or external-writer comparison cannot be proved, the runtime preserves its private recovery evidence, returns `RECOVERY_REQUIRED`, and refuses every later apply until a recovery attempt is proved. No partial state is reported as success. |
| Resolver rule | The current artifact-tree resolver receives only the canonical tuple of family, root ref, ordered explicit refs and node metadata. R09B adds no string lookup or sibling search. | Runtime-fault rule | Expected resolution outcomes are the resolver's finite decisions. A narrow, explicit runtime-invariant failure during post-proof is fail-closed after recovery and receives a named sanitized result; the implementation must not add a broad exception normalizer. |

## Non-negotiable properties

1. `RECOVERY_REQUIRED` is a state with zero target-document effects after it is observed; it is not a successful retry, delivery claim or automatic repair.
2. The recovery record and private snapshots may contain prior target bytes only in the local runtime recovery boundary. They never cross Router state, result metadata, logs, prompts, telemetry, Provider or host-adapter output.
3. An advisory lock protects cooperating runtime instances only. An external writer that ignores it is not overwritten; conflicting bytes preserve the recovery-required state.
4. Existing exact-path resolution remains canonical. No ticket may add discovery, fuzzy matching or alias preference to obtain a post-state result.
5. The correction retains valid R09A planning, artifact-tree and legacy target-document tests. It does not reuse either rejected R09B candidate as implementation authority.
