## Downstream constraints

1. The resolver must preserve the pure provider-neutral boundary: it accepts normalized injected data and returns only a finite `RouteResolution`; it does not read configuration, write state, or invoke a provider or host.
2. Canonical revalidation covers every nested table, registry, profile, assessment, and verification object. `model_construct`, `model_copy`, casts, historical instances, and unvalidated dynamic data are negative-only inputs and cannot establish a selected result.
3. The new finite status values are additive; every exhaustive status consumer, serialized-status allowlist, and strong-type test must be revised before approval.
4. A replacement ticket must cover malformed table and registry graphs; missing/null profile evidence; typed self-asserted/unverified/stale/unknown assessment states; missing verification record; cross-ticket/wrong-closure verification; and bypass-created nested objects. It must preserve the existing normal route, no-fallback, unavailable-profile, override, bounded-cycle, and no-effect boundary coverage.
5. The replacement ticket remains `POC` / `STANDARD`. Its applicable evidence is the document-mutation gate plus the reviewer-owned independent reverse mutation. `KNOWN_GAP_WORKSPACE_BINDING_READBACK_UNAVAILABLE` remains a named host gap, not workspace/profile/rank, receipt, runner, delivery, or wake evidence.
6. Until the revised Context, SPEC, and replacement ticket are approved, no P8R source candidate is dispatch, commit, integration, push, release, or deployment authority. This leaf returns `REQUIREMENT_CHANGED`; it creates no shortcut around review.
