## Effective product rule

RWW6 remains non-negotiable. A managed-artifact runtime must not write, replace, unlink,
reset or otherwise mutate the target worktree directly. It may apply one validated
`ManagedArtifactPlan` only by building one complete candidate Git commit from one directly
observed authority-ref commit, then requesting one non-force, fast-forward-only update of that
declared remote authority ref.

The observed authority commit is the identity of the complete managed document tree. The
candidate must have that exact commit as its sole parent and contain every planned create,
revise, replace or archive mutation in one tree. If an independent writer advances the same
authority ref after observation, the final authority update must reject; the runtime must not
rebase, merge, force-push, reset, delete the ref, overwrite a local worktree or retry against a
new head implicitly.

Success is only `AUTHORITY_INTEGRATED`: direct remote readback of the declared full ref equals
the candidate commit after a successful non-force update. A rejected stale head is
`STALE_AUTHORITY` with zero target effect. A network or server outcome that cannot be resolved by
direct readback is `PUSH_UNCONFIRMED`; it is fail-closed and may not retry. A later correction is
one newly reviewed forward commit based on a newly observed authority commit.

## Non-negotiable properties

1. No R09 successor may fall back to `os.replace`, `rename`, `unlink`, a local Git ref update,
   a shared-worktree write, force push, reset or remote-ref deletion.
2. The candidate tree is complete, canonical and has exactly the directly read authority commit as
   its sole parent; remote-tracking refs and a previous fetch are diagnostics, never authority.
3. The final authority transition is one declared full branch ref through a non-force
   fast-forward-only server operation, followed by direct remote SHA readback. Qualification must
   also prove that the authority ref rejects force, deletion and an ordinary bypass update; without
   that policy, a ref can return to an old SHA and invalidate the conditional identity claim.
4. Stale authority, policy rejection, unavailable credential/transport and ambiguous delivery are
   finite no-effect results. None authorizes automatic rebase, merge, retry or compensation.
5. An actual authority remote must independently prove the conditional transition with two
   competing candidates from one baseline. Documentation, a local bare repository, an API name or
   a different remote are not proof for that authority contract.
6. Recovery after an integrated commit is forward-only: a new reviewed candidate from the latest
   authority commit. The runtime never rewrites authority history to roll back.
