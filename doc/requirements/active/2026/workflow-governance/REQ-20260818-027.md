# Intake modes, product kinds and the typed NormalizedGoal

| Field | Value |
| --- | --- |
| PRD / change | `PRD-20260818-027` / `CHG-20260818-027` |
| Lifecycle | `ACTIVE` |
| Old rule | INTAKE's "goal normalization" had no schema, so Wayfinder's input was undefined. The method assumed a greenfield user-facing product: every project had to produce frontend slices, a business model, market validation and a cost ceiling, or be vetoed — CLI/service/library/control-plane targets and inherited projects could not pass truthfully. |
| New rule | INTAKE emits one committed typed `NormalizedGoal` (`intake_mode`, `product_kind`, bounded goal statement, constraints, evidence refs, `baseline_reference`, `delta_scope`), Wayfinder's sole goal authority. `GREENFIELD` runs the full evaluation; `TAKEOVER` binds `<repo-id>@<commit>` and replaces business/cost derivation with an existing-baseline veto; `DELTA` re-converges only the named affected slices. Slices generalize to observable outcomes whose interaction boundary follows `product_kind` (screen/page/flow, API endpoint, CLI command, event contract); business/cost veto items are GREENFIELD-scoped. Paths and URIs are untypable in the baseline binding. |
| Rationale | Wayfinder vetoed viable non-UI and inherited projects (including this plugin itself) and demanded evidence that does not exist outside greenfield product discovery, forcing fabrication or a false NO-GO. |
| Impact | `library/workflow_router/contracts.py` (`IntakeMode`, `ProductKind`, `NormalizedGoal`); `Defined_wayfinder.md` (mission, intake table, observable slices, mode-scoped Business/Feasibility/Strict Veto, Required Output); `references/discovery-change.md`; `references/router-control.md` INTAKE row; new `tests/test_wayfinder_intake_modes.py`. |
| Acceptance source | `Defined_wayfinder.md`; `tests/test_wayfinder_intake_modes.py` |
