# Independent adversarial review and deployment readiness

| Field | Value |
| --- | --- |
| PRD / change | `PRD-20260827-042` / `CHG-20260827-042` |
| Lifecycle | `ACTIVE / OWNER_APPROVED / ARCHITECTURE_DECIDED / REVIEWER_DECOMPOSITION_AUTHORIZED` |
| Authority | Project owner, 2026-08-27 (Asia/Taipei): authorizes ticket-level reviewer-arranged adversarial review and a deployment-readiness attack matrix. |
| Requirement | A ticket reviewer may obtain a bounded, independent adversarial audit, but retains the sole review conclusion and integration authority. Any release or deployment requires a candidate-bound readiness matrix that tries to falsify applicable correctness, data, compatibility, operational and observability claims before the effect. |

## Change record

| Field | Value |
| --- | --- |
| Old rule | `CodeReview.md` requires reviewer-owned counter-mutation and `HIGH_ASSURANCE` mentions adversarial verification, but neither gives a reviewer a ticket-bound independent-audit contract or gives a release/deployment an applicability-based attack matrix. `review-checks.md` also describes live descriptor/receipt evidence as though it applied to every multi-Agent review. |
| New rule | The reviewer may schedule one bounded, same-lifetime, read-only-intent adversarial auditor after the candidate exists. The auditor returns only evidence-backed findings or a finite unavailable/blocked result; it cannot approve, integrate, commit, push, change a ticket, access a secret, or execute an external effect. A reviewer still performs the independent review and decides the conclusion. `HIGH_ASSURANCE` review and every proposed release/deployment require the declared adversarial evidence and applicability matrix. |
| Scope | Specification completeness, boundary data, state order, concurrency, errors, authorization, consistency, idempotency, regression and observability; when applicable, migration, historical data, compatibility, rollback, environment/configuration drift, lock/pool/worker/cache behavior, interruption/recovery, backup/restore, smoke and authorized account sampling. |
| Effect boundary | The matrix is review evidence, not authority. A production-data sample, real-account action, secret/configuration read, migration, release or deployment remains a separately scoped external effect under `security-boundary.md`. |
