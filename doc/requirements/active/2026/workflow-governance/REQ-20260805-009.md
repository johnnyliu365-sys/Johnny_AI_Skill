## Delivery-continuity amendment — reviewed design, runtime not yet effective

The project owner's 2026-10-18 checklist refines this existing workflow-governance
requirement; it does not create a second PRD. The reviewed SPEC design keeps the
cross-ticket work mainline separate from one ticket's closure, continues unrelated admitted
work while another ticket waits for a human-owned effect, and binds completion to the
necessary candidate-version, test, review and dependency evidence. A correction must reuse
the original requirement, ticket, budget and previously valid evidence; a reviewer may
recheck the affected consumers but may not turn unrelated hardening into a new closure item.

Production code **and test scripts** must retain explicit, independently reviewable
responsibilities. A ticket must identify existing modules and shared test harnesses to
reuse before authorizing a new file, name each new file's distinct responsibility, and
declare the actual modified/created/deleted paths. The sanctioned integration path must
reject undeclared paths from the Git diff. Growth of a large or multi-responsibility file
requires a recorded structural review of the real candidate, not a line-count-only pass,
automatic file splitting, or a fresh PRD that leaves the coupling untouched. Reviewer
evidence must distinguish a product responsibility split from a test-script rearrangement.
