# Baseline-red redefinition and COMPACT ceremony reduction

| Field | Value |
| --- | --- |
| PRD / change | `PRD-20260818-029` / `CHG-20260818-029` |
| Lifecycle | `ACTIVE` |
| Old rule | First-red evidence was required for every behavior at every intensity, although a red run against not-yet-existing code proves nothing when one agent writes test and implementation together. COMPACT changes still paid the full closure ceremony: separate handoff leaves and full evidence tables. Test exemption did not exist, so zero-value tests were written for docs, comments, schema-validated config and type-checked renames. |
| New rule | Red evidence is redefined at every intensity: defect corrections must record baseline-red (the test failing on the defective baseline), which is real evidence; new behavior records green tests at the approved seam with no ceremonial first-red, and test quality is proven by reverse mutation at `HIGH_ASSURANCE`. COMPACT closes as commit-as-handoff — one implementation commit carrying AC, results and digests, no separate handoff leaf or evidence table. A typed `ChangeClass` declaration (`DOCS_ONLY`, `COMMENT_ONLY`, `SCHEMA_VALIDATED_CONFIG`, `TYPE_CHECKED_RENAME`) skips test writing at any intensity, fails closed for any foreign value, and is voided by any production-behavior effect. Tests as review evidence remain mandatory everywhere else: ceremony scales with future readers and writer distrust, not with project size. |
| Rationale | Owner decision after cost analysis: test execution costs no model tokens, but staged first-red narration, per-ticket evidence tables and handoff leaves are model-output costs whose value depends on future readers. Small work has none; the ceremony was pure waste there while the actually valuable guarantees (baseline-red for bugs, reverse mutation for test quality, state compression for multi-lane work) are preserved where their consumers exist. |
