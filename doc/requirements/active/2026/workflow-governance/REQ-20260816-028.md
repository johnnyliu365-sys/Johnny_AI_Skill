## Required behavior

1. The consumed `BDG-R03-01-20260816-001`, delivery evidence, implementation commit and sealed
   review remain immutable. They authorize no correction, integration or source reuse.
2. The original `R03-01-CS-01` is terminal `TICKET_DEFECT / NON_INTEGRABLE`; R03-02 and R03-03
   remain blocked until its approved replacement dependency chain is integrated.
3. The replacement chain has four independently verifiable closures: `R03-01A` public contract
   freeze, `R03-01B` durable owned-state transaction substrate, `R03-01C` approved-artifact
   registry, and `R03-01D` TicketReceipt CAS store.
4. `R03-01B` is real production source over an injected Johnny-owned root capability. It uses
   Python standard-library filesystem/locking primitives, one bounded journal plus generationed
   checkpoint replacement, and exact interruption recovery. A Protocol or in-memory fake cannot
   satisfy it.
5. No SQLite, database service, network service, MCP state, target-project state, new runtime
   package or raw path/URI field is introduced. Partition locators are digest-derived inside the
   adapter and remain ledger-owned relative paths.
6. The durable boundary acquires one non-recurring exclusive lock attempt, validates the current
   generation, records a prepared transaction, atomically replaces a flushed checkpoint, records
   settlement and verifies readback. Lock contention or ambiguous/corrupt recovery fails closed;
   there is no sleep, retry loop, heartbeat or polling.
7. R03-01C and R03-01D consume the integrated state-store port. They own their separate domain
   behavior and cannot substitute a process-local map, delegated fake or untyped blob.
8. Every replacement bootstrap phase requires its own exact committed ticket and owner-approved
   no-receipt grant. Only after reviewed R03-01D integration may R03-02 receive a real
   `TicketReceipt` plus its temporary transport grant.
9. Strict typing uses `--strict --explicit-package-bases --no-incremental` with an external cache.
   Implementers run focused commands for their exact closure; the Senior runs the full affected
   and repository matrix once during isolated review. The obsolete ambiguous-package command is
   not reused.
10. The Senior may inspect Git evidence read-only, but every command that can create cache,
    bytecode, temporary runtime state or test files runs in a Senior-owned disposable clone/root
    of the exact commit. The Senior never cleans or mutates an Implementer worktree.

## Transition

- Owner approval replaces only the failed R03-01 decomposition and the affected Revision-04
  bootstrap allowlist. All normal receipt, grant, claim-before-effect, user relay, no-heartbeat,
  integration and activation invariants remain unchanged.
- Approval authorizes Architecture to seal Revision 05 and Senior to create fresh decomposition
  and ticket leaves. It creates no grant, receipt, task, worktree, branch, dispatch, integration,
  push, release or deployment authority.
- Until approval, the Router remains `WAIT_FOR_HUMAN`; no replacement bootstrap ticket is
  dispatchable.
