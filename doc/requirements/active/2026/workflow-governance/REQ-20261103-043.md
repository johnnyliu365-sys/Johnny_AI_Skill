| Control-plane disposition 2026-11-19 (generic lesson L-23, under the owner decision "B") | Norms and checks are two mechanisms on two triggers: norms (principles for the whole session) are injected at wake (session start, resume, after compaction); checks (item-by-item on the one thing about to be sent) fire before or after the action, as hooks. Checks come in three strengths chosen by whether a program can decide them: block before the action when decidable and serious (for example a push to a protected branch, a force push, a commit identity other than the repository one); warn first, then block, when decidable but error-prone (for example a new ticket file without its index row); compare automatically after the action (for example a ticket state row against the index). | Control-plane disposition 2026-11-19 (L-23 addendum: a hook must not depend on the working directory) | Observed in another project on 2026-11-19. A session changed its working directory into a fixture folder. Its pre-submit check hook located its own script relative to the working directory, failed to find it, and blocked every shell command, PowerShell included; the session could not run the command that would have fixed it until the turn ended. The same class exists here in a milder form: the user-level SessionStart hook reads `AGENTS.md` by a relative path, so after a directory change it silently skips the injection. Wave 4, with the L-23 hooks: (1) a hook resolves its script and every file it reads from the project root the host passes (`CLAUDE_PROJECT_DIR`), never from the session's working directory; (2) a hook that cannot find its own script prints the path it tried and the recovery; it blocks only the action it checks, never every command, so the session can still run the command that recovers; (3) a regression case runs every hook from a subdirectory of the project. The other project's session then unblocked itself by changing the four hook script paths in its untracked `.claude/settings.local.json` to absolute paths. That fixes one checkout only: in a worktree session the absolute path runs the main checkout's copy of the check, not the worktree's, and a clone or a worktree may not carry an untracked settings file at all. Wave 4 therefore also (4) keeps check hooks in the versioned `.claude/settings.json` with `CLAUDE_PROJECT_DIR` paths, and verifies that a worktree session runs them. |
