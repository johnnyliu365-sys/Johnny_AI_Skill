# Wayfinder scope reduction and termination rule

| Field | Value |
| --- | --- |
| PRD / change | `PRD-20260818-026` / `CHG-20260818-026` |
| Lifecycle | `ACTIVE` |
| Old rule | Wayfinder's Required Output demanded architecture-grade completeness per slice: a seven-field data pipeline and a full `composition_and_di` block (Composition Root, injected dependencies, lifetime scope, test fakes). Strict Veto forced `NO-GO` when a slice could not name them. The slice map had no completeness bound, so evaluation expanded instead of converging, and the mission's "do not make architecture choices" contradicted its own output schema. |
| New rule | Wayfinder converges on viability only. Slices are bounded: every `mvp_scope` item maps to at least one slice and the slice count is capped at the `mvp_scope` item count. The function-derived map is coarse (use cases, domain rules, data owners, open assumptions, separability flag). Wayfinder checks only separability plausibility; the complete data pipeline and the full composition/DI/lifetime/test-fake map are Architecture's mandatory output and Architecture's completion blocker. |
| Rationale | Discovery-stage demands for architecture decisions caused oscillation between "don't decide architecture" and "the schema forces me to", and unbounded slice lists had no fixpoint. Observed as Wayfinder non-convergence in live takeover use. |
| Impact | `Defined_wayfinder.md` (Evaluation 2–4, Strict Veto, Required Output, Handoff); `skills/johnny-project-takeover/references/discovery-change.md` (Architecture mandatory output and gate). No executable-contract change: `WayfinderInputField` already omits composition/DI fields, which this change makes consistent. |
| Acceptance source | `Defined_wayfinder.md`; `skills/johnny-project-takeover/references/discovery-change.md` |
