## Required behavior

1. Preserve `R03-00-CS-01`, registry `e0a710d217624cd90f902e14fe216d945e5ef0fa`,
   `BPB-R03-00-20260816-001`, its review/clarification records,
   `BDG/BDA/BDR-R03-00-20260816-001`, attempt commit
   `a7cb3d011594f4a08cfa7a925ae7888231ed381d`, delivery commit
   `336238ed71c24dc0487013775cb269d884d186ce` and the Implementer halt as immutable, consumed
   historical evidence. None may authorize a retry.
2. `BPB-R03-00-20260816-002` may cover only project `AI控制工作workflow`, ticket
   `R03-00-policy-correction-prerequisite` and successor closure `R03-00-CS-02`. It gives no
   authority to R03-01A through R03-01D.
3. The Senior must independently approve the exact successor bridge commit before creating a new
   ticket/admission leaf. The new ticket source itself must state
   `ADMITTED_FOR_BPB_ROUTE / HIGH_ASSURANCE_REQUIRED / OWNER_GRANT_REQUIRED`; it must bind the
   actual proposed execution identity and must not inherit `BLOCKED`, `NON_DISPATCHED` or
   `BOOTSTRAP_POLICY_BRIDGE_MISSING`.
4. The new immutable registry and admission decision must bind the exact successor ticket blob
   and digest. Any later grant must bind those exact values; no later artifact may override a
   mismatched ticket source.
5. The new grant uses `baseline_rule=CLAIM_INTRODUCTION_COMMIT`, not an earlier fixed execution
   commit. After exact owner approval, the Senior commits one consuming attempt; the Git commit
   that first introduces that attempt is derived through Git readback and becomes the exact
   implementation branch baseline. That commit must contain the successor bridge, approved
   review, ticket registry and approved grant.
6. The attempt-introduction commit cannot contain its own hash. The derived commit ID is supplied
   in the one-shot identifiers-only dispatch envelope and validated against Git ancestry and
   artifact readback before implementation mutation.
7. `HIGH_ASSURANCE_REQUIRED` is an assurance lane, not an automatic model name. Senior selects
   the model/profile under the delivery profile; the exact successor ticket and later owner-
   approved grant must agree.
8. The route remains a manual, project-specific bootstrap bridge. It does not claim live Router,
   receipt, subscription, wake or normal-dispatch capability. Heartbeat, recurring reads, polling,
   automation, push, release and deployment remain forbidden.
