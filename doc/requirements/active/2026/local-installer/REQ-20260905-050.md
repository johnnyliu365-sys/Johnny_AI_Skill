## Old and new rule

Old future delivery: Inno Setup `Setup.exe` plus its matching scripted uninstaller,
under a single writable installer-owned root. Tickets 04A–04I describe that unbuilt
package. They must not continue under their old assumptions.

New delivery target: a signed Windows per-user MSIX package, with package-manager-owned
immutable application files, separately owned mutable runtime state, and explicitly
verified Codex/Claude host activation. A `.msixbundle` is justified only if multiple
architectures require it. Renaming a ZIP/EXE to `.msix` is not completion.

The existing local-first, detachable, metadata-only control-plane goals remain. No
plugin runtime/dependency is added to a target project. Format-neutral ownership,
fail-closed recovery, target isolation and immutable source/artifact lineage remain
requirements; `PRD/CHG-20260808-011` and `PRD/CHG-20260812-014` remain active for those
parts. This change supersedes their Inno-specific future packaging assumptions only.

## Owner removal decision — accepted 2026-09-05

The old one-click uninstall guarantee included package-external host registrations.
Ordinary MSIX removal must not be assumed to invoke an arbitrary Johnny cleanup
script. The owner accepted **Johnny-managed one-click complete removal**: stop owned
work, remove and freshly verify owned Codex/Claude integrations, settle owned state,
then remove the exact MSIX package and independently prove absence. A failure must
retain recovery evidence and must not report complete removal.

Direct Windows uninstall has a narrower guarantee: only the measured Windows package
scope; it does not promise cleanup of package-external host registrations. This limit
must be visible before host activation and in removal guidance, not hidden in a log.
No signing identity, certificate trust distribution or company-machine policy
exception has been authorized. Self-removal/result readback still needs capability proof.

## Impact and completion boundary

- Re-converge installer SPEC AC-01/02/03/06/07/12 and package composition/root rules.
- Stop the unstarted Inno 04B path; 04A and 04C–04I require MSIX refreeze, not blind
  reuse of old source/toolchain/artifact authority. Finished historical tickets remain unchanged.
- Keep existing CLI/ZIP installation usable until a qualified migration exists;
  never delete an existing installation merely to make an MSIX test pass.
- Qualify install, host activation, upgrade, interrupted operation, recovery,
  complete removal and direct Windows removal separately in a disposable Windows user.
- Verify both Codex and Claude independently; a package install is not host activation,
  an activated host is not an armed cross-lifetime bridge, and missing bridge does not
  block synchronous delegation.
- Publish/install no MSIX until exact source, SDK/toolchain, dependencies, package
  identity, signature trust and real lifecycle evidence are bound to one candidate.
