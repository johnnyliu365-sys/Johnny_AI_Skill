## Stable product and authority boundaries

- Controlled verification binds approved intent to executable checks, finite resource/lifetime
  limits and independently observed evidence. It does not replace the existing Router, ticket
  reviewer or repository integration authority.
- D1 rejects responsibility mixing and forbidden coupling, not file size. Existing WA-04 owns
  source-derived responsibility admission; a numerical line ceiling is not an acceptance proxy.
- D2 confines restricted execution/policy protection to explicitly enrolled Johnny sessions and
  worktrees. Unrelated projects and owner-operated terminals are unchanged.
- D3 selects a dedicated launcher, restricted Windows subject and separately protected broker/
  policy/evidence owner. Capability investigation is confined to the existing Windows lab with
  no physical-host configuration changes or external model calls.
- Python 3.11 remains the proposed single backend language. Native platform transport stays at
  injected edges. Production primitives must be qualified before dependent adapter admission;
  unsupported capability is not a successful fallback.
- Target source, tickets and approved intent stay target-owned; Johnny control components and
  operational state stay outside target runtime. Credentials and raw operational material do not
  enter Router metadata. Approval, execution observation, review and integration remain separate.
- Codex and Claude require independent exact-surface qualification. CLI evidence is not Desktop
  evidence. Same-lifetime delegation needs no durable runner/queue/receipt and uses event waiting.
