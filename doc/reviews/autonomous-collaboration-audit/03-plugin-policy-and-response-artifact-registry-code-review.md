## Blocking findings

### CR-32 — Approved-dispatch artifacts are not scoped to the opaque project

**Impact:** an approved-artifact record is keyed only by ticket, handoff and implementation-owner IDs. The normal private pending maps already include account and project, but admission occurs first and has no project identity in its registry query. If one account is entitled to two projects and both requests use matching valid-shaped ticket/handoff/owner/commit metadata, the second project resolves the first project's reviewed record and gets a pending dispatch. The issue is an authorization and project-isolation failure, not merely a collision convention.

**Independent reproduction:** a fresh private client was configured with valid entitlements for `prj_fedcba9876543210` and `prj_1111111111111111`, while the registry contained a record only for the first. Replaying the otherwise identical valid request under the second project returned `wait_for_human` with a non-null pending descriptor.

**Evidence:** `library/workflow_router/policy_response.py:127-203` defines, stores and resolves `ApprovedDispatchArtifact` without a project key. `library/workflow_router/router.py:248-275` calls that resolver without `RouterState.project_id`; `library/workflow_router/private_router.py:823-840` calls it without `RouterRequestEnvelope.opaque_project_id`. This conflicts with the same file's own pending-map scoping at `private_router.py:613-625` and with the project-scoped dispatch authority required by SPEC AC-3.

**Required correction:** add a strongly typed opaque project ID to `ApprovedDispatchArtifact`, its registry resolve interface and the duplicate-identity key. Pass `RouterState.project_id` in direct Router admission and `RouterRequestEnvelope.opaque_project_id` at the private client boundary. A record must match the exact project, ticket, handoff, named owner and both commits before any pending state exists. Write red/green direct and private regressions in which a second entitled project reuses all other valid values; assert `HALT`, no response text, no pending descriptor, no receipt acceptance and no ticket-lane capability. Preserve current same-project positive behavior.

### CR-33 — Docs-only handoff is not an unambiguous audit sequence

**Impact:** `WorkProgressReport.md` is formal completion evidence. The submitted version uses `PRG-20260808-006` for two different records and places its rebase-aware PRG-009 ahead of PRG-007 and PRG-008. A reviewer cannot recover a unique chronology or cite a record label without ambiguity.

**Required correction:** in the next docs-only handoff, retain the historical validation content but restore a unique, chronological audit sequence (including an explicit correction/erratum if an already-recorded identifier must be preserved).
