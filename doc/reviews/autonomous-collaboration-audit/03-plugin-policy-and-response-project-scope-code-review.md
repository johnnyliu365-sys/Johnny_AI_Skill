## Blocking findings

### CR-33 — WorkProgress remains non-chronological and ambiguously numbered

**Impact:** the docs-only handoff did not perform the required audit correction. Its new PRG-010 entry is inserted before PRG-009, PRG-007 and PRG-008; the duplicate PRG-006 records also remain. Completion evidence cannot be cited or read as one unambiguous chronology.

**Evidence:** `doc/WorkProgressReport.md:300-397` orders the Ticket-03 history as PRG-006 allocation, a second PRG-006, PRG-010, PRG-009, PRG-007 and PRG-008.

**Required correction:** preserve the historical validation facts, but assign unique record identities and order the records chronologically. Append the next docs-only handoff only after the corrected sequence, with its exact verification evidence.

### CR-34 — The private cross-project regression is not an authority-bypass test

**Impact:** the committed test sends the alternate-project request through a client whose `FakeEntitlementProvider` contains only the original project. A future client-side registry regression could still yield `halt` because the service would deny entitlement, so the test does not prove the required private admission guard against an entitled cross-project replay.

**Evidence:** `tests/test_plugin_policy_and_response.py:434-472` uses `self.client`; its `setUp` grants only `self.project` at lines 166-173. The test has no alternate-project `EntitlementGrant`.

**Required correction:** create a fresh private service/client in the test with two valid grants for the same account. Keep the registry record only for the original project, replay every other valid field through the alternate project, and assert `HALT`, no response text, no pending descriptor, no receipt acceptance and no ticket-lane capability.

### CR-35 — Registry project identity is not a typed opaque identifier

**Impact:** `NonBlankText` accepts arbitrary non-empty text, including raw paths and traversal fragments. The approved-artifact model can therefore retain non-opaque location content in a Router boundary and does not meet the P0 strong-type rule or the specification's opaque project-ID contract.

**Evidence:** `library/workflow_router/policy_response.py:130,144,172,193` types project identity as `NonBlankText`. Independent construction accepted `C:\repo\..\unscoped-project` as `project_id`.

**Required correction:** define and use one named, validated opaque `ProjectId` value type for approved dispatch artifacts and registry resolution. It must reject null, empty, whitespace, path, URI and traversal representations before registration or resolution. Retain valid current project IDs and the existing project-scoped equality rule.
