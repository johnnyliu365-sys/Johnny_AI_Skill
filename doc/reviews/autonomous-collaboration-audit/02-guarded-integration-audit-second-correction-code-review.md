## Finding

### CR-23 — Audit delivery is not admission-controlled, allowing duplicate Grill audit requests

**Impact:** `retry_pending_audit()` treats `_pending_audit_delivered` as a post-call flag. While `AuditSink.request_audit()` is running, the flag remains false and neither `retry_pending_audit()` nor the sink invocation has a delivery-in-flight guard. A re-entrant or concurrent retry can therefore issue a second audit request for the same `PendingAudit`. This breaks the ticket's one-integration/one-Grill-audit invariant and can route the same `INTEGRATION_COMPLETED` event twice. It is not a new human wait and must fail closed.

**Independent reproduction:** A trusted completed return was sent to the coordinator with an injected audit sink. On its first `request_audit`, that sink synchronously called `GuardedIntegrationRouterAdapter.retry_pending_audit()`. The result contained one integration request but **two** audit-sink requests. Both paths emitted the identical `audit-audit-reentrant-01` integration event. With a first delivery failure followed by the same re-entry on retry, the sink recorded three requests (one failed attempt and two duplicate retry attempts).

**Evidence:** `library/workflow_router/guarded_integration.py` assigns `_pending_audit_delivered = True` only after the fallible `request_audit()` call returns. `retry_pending_audit()` has no separate delivery state or non-reentrant admission check. The submitted retry test covers sequential calls only, so it cannot observe an interleaving during the sink call.

**Required correction:** Model audit delivery as a typed, coordinator-owned state machine such as `RETRYABLE`, `DELIVERING`, and `DELIVERED`. Atomically mark the pending audit `DELIVERING` before calling the injected sink. A second call while delivery is in flight must return a stable fail-closed decision with no request or Router event; on a sink exception reset only to the declared retryable state, and on success transition once to delivered. Preserve the existing global `PENDING_AUDIT` isolation and ensure dependent waking and event emission occur exactly once. Add deterministic re-entrant and concurrent delivery tests for both the initial request and a retry after failure.
