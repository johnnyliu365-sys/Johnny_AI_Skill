## Finding

### CR-24 — A failed or never-delivered audit can be approved directly from `RETRYABLE`

**Impact:** `handle_audit()` rejects only `DELIVERING`. It accepts a matching decision in `RETRYABLE`, including the state left by a failed `AuditSink.request_audit()`. This allows the pending audit to be consumed and routes the ticket to Code Review even though the Grill audit was never successfully requested or delivered. It bypasses AC-7's required immediate audit and conflicts with AC-8's fail-closed handling of unavailable adapters.

**Independent reproduction:** With a valid receipt-bound implementation return and an injected sink that throws on its first request, `handle_return()` correctly returned `HALT + ADAPTER_FAILURE`, retained one pending audit, and recorded one **failed** sink call. Before any retry succeeded, supplying a matching `AuditDecision(APPROVED)` to the adapter returned `CODE_REVIEW` plus `AUDIT_COMPLETED` and cleared the pending audit. No successful audit delivery occurred.

**Evidence:** `library/workflow_router/guarded_integration.py` resets `_audit_delivery_state` to `RETRYABLE` on sink exception. `handle_audit()` verifies ticket/correlation and rejects only `DELIVERING`; it does not require `DELIVERED` before consuming `_pending_audit`. The submitted re-entry/concurrency tests cover admission while delivery is active, but do not attempt an audit decision while delivery is retryable after failure.

**Required correction:** Accept an audit decision only from the typed `DELIVERED` state. `RETRYABLE` and `DELIVERING` decisions must halt with a stable non-delivery error, preserve the pending audit, leave all review/handoff/deploy grants false, and emit no Router event. Add deterministic tests for approved and changes-requested decisions after a failed initial delivery and after a failed retry; both must prove no audit completion event, no Code Review/correction route, no pending-state consumption, and no additional integration. Retain the CR-23 re-entry and concurrent-delivery guarantees.
